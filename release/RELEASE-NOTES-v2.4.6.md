# NegativeCutter v2.4.6

v2.4.6 同时更新 Lightroom Classic 插件和 macOS 独立版，新增单排 120 检测，并修复两类会直接影响裁切结果的问题。

## 本次更新

### 单排 120 胶片检测

- 支持 645、6×6、6×7、6×8、6×9 单排扫描
- Auto 模式会自动判断 135/120 路径和帧数；也可手动指定画幅
- 120 间隙检测改为三段图像共识，减少山脊、建筑、天空等画面强边缘造成的误判
- 不再强制把整条胶片的所有间隙改成相同宽度，保留扫描中的真实间距差异
- 645 的 4:3 比例已纳入 120 格式注册表，不会误用 4×5 片材的 5:4 比例

两条真实 120 TIFF 已建立人工像素边界和文件指纹回归。旧算法在这两条样本上的最大超带误差为 58 px、152 px；v2.4.6 的内部间隙和跨轴边缘均落入人工标注范围。当前真实样本数量仍有限，这项结果不代表所有扫描仪、片基和 120 画幅都已完成实拍覆盖。

### Lightroom 插件

- 新增识别后的裁切预览，可用上、下、左、右四个像素偏移微调
- 支持逐张预览、整批统一、不预览三种处理方式
- 增加原生批次进度和取消；取消不会删除已经创建的虚拟副本
- 修复 EXIF orientation 5/7 对应的 `AD/CB` 方向映射，避免 120 帧被写成狭长竖条或镜像裁切
- 批处理中单张失败后会继续处理后续照片；零成功批次正确显示为失败
- 加固预览临时文件、串行渲染和关闭清理流程
- 修复带 EXIF orientation 5/7（Lightroom 中常见为 `AD/CB`）的 120 TIFF 预览方向不匹配：预览使用缩略图坐标，用户确认后才转换为 Lightroom 最终裁切坐标
- 逐张预览与整批统一模式采用同一坐标转换契约；整批像素偏移先在预览坐标中应用，再转换到每张照片自己的 Lightroom 方向

### macOS 独立版

- 长条扫描缩放到窗口后，框线命中范围按屏幕像素计算，边缘和角点恢复可拖动
- 框线宽度不再随图像缩放变得难以看清
- App、Lightroom 插件、API 和 macOS Bundle 版本统一为 2.4.6

## 安装

### Lightroom Classic 插件

1. 下载并解压 `NegativeCutter-135-v2.4.6.zip`
2. 在解压目录运行顶层 `install.sh`
3. 重启 Lightroom Classic
4. 在“文件 → 增效工具管理器”确认 NegativeCutter 正在运行

### macOS 独立版

1. 下载并解压 `NegativeCutter-135-v2.4.6-Standalone.zip`
2. 将 `NegativeCutter.app` 移入“应用程序”
3. 首次启动若被 Gatekeeper 拦截，请右键 App 后选择“打开”

## 系统要求

- macOS 11 或更高版本
- Apple Silicon（arm64）
- Lightroom 插件需要 Adobe Lightroom Classic 10.0+
- 无需安装 Python 或其他运行库
